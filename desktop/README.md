# VoltGuard — Week 2

Physics-Aware ICS/SCADA Intrusion Detection System
**Week 2 milestone:** Bridge Integration + Native Dashboard foundation

## What's new since Week 1

- `modbus_parser.cpp` now supports a `--json` flag that emits one JSON
  object per parsed frame (JSON Lines), so other tools can consume its
  output instead of just reading printed text.
- **`src/network_physics_bridge.py`** (the actual "Bridge Integration"
  deliverable): runs the C++ parser as a subprocess, feeds each parsed
  pump-speed command's RPM value into `physics_model.evaluate_command()`,
  and writes a combined report (`data/bridge_report.jsonl`).
- **`dashboard/`**: foundation of a native Qt C++ desktop app. It loads
  `bridge_report.jsonl` into a table and highlights CATASTROPHIC rows.
  No live traffic feed or real-time graphs yet — that's Week 3.

## Setup

```bash
pip install -r requirements.txt --break-system-packages
./build.sh
```

`build.sh` always builds the C++ parser. It builds the Qt dashboard too,
if `qmake` (Qt dev tools) is available on your machine — otherwise it
skips that step and tells you what to install
(`qtbase5-dev` on Ubuntu/Debian, or Qt Creator's bundled Qt on
Windows/macOS).

## Run order

1. **Generate mock traffic** (same as Week 1):
   ```bash
   python3 src/traffic_generator.py
   ```

2. **Run the bridge** — this replaces manually running the parser and
   physics model separately:
   ```bash
   python3 src/network_physics_bridge.py
   ```
   This will:
   - call `./modbus_parser data/traffic_log.bin --json` under the hood
   - feed each pump-speed command's RPM into the physics engine
   - print a SAFE/CATASTROPHIC table to the console
   - write `data/bridge_report.jsonl`

3. **Open the dashboard** and load the report:
   ```bash
   ./dashboard/voltguard_dashboard
   ```
   Click **"Load Bridge Report..."** and select `data/bridge_report.jsonl`.
   CATASTROPHIC commands (e.g. the 50,000/60,000 RPM attack frames) are
   highlighted in red.

## Notes / design choices

- The bridge does **not** drop or block anything yet. It only observes
  and reports. Inline blocking (the actual IPS behavior, sub-10ms
  latency, Rust) is Week 3 per the plan.
- JSON Lines was chosen as the interchange format between C++ and
  Python because it's trivial to parse on both sides without pulling
  in a heavy JSON library in C++, and it's easy for the Qt dashboard
  (via `QJsonDocument`) to read too.
- The dashboard purposefully has no live connection to the bridge yet
  (it reads a static report file) — real-time predicted-vs-actual
  graphs come in Week 3 per the plan.
